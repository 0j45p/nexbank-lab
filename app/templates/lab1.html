Method B — OTP Bypass Parameter

          
Flaw: otp_bypass=true in request body skips OTP validation entirely

        

        
⬜

      

      

        
The /api/auth/verify-otp endpoint checks for otp_bypass before validating the OTP. Sending "otp_bypass": true immediately returns a verified session — no OTP needed.


        

POST /api/auth/verify-otp

{

  "mobile": "9100000002",

  "otp_bypass": true

}
        


        

          
          
        

        

      

    


    
    

      

        
C

        

          
Method C — Rate Limit Bypass via X-Forwarded-For

          
Flaw: Rate limiting uses X-Forwarded-For header — attacker-controlled, allows unlimited OTP sends

        

        
⬜

      

      

        
The server limits OTP requests to 5 per IP per 60 seconds — but the IP is read from the X-Forwarded-For header which is attacker-controlled. Changing it each time bypasses the limit, allowing brute-force of a 6-digit OTP (1,000,000 combinations).


        

POST /api/auth/send-otp

X-Forwarded-For: 10.0.0.[increment] ← spoof IP each time

{"mobile": "9100000002"}
        


        
Simulate: send OTP 10 times with rotating IPs — no rate limit hit.
