IDOR — Fetch Another User's Profile
Flaw: GET /api/account/user/{user_id}/profile — no ownership check, user_id is attacker-controlled
⬜

The profile endpoint returns PAN number, Aadhaar, password hash and KYC details for any user_id. The server checks only that a JWT is present — it never verifies the JWT's user_id matches the requested resource.

GET /api/account/user/{user_id}/profile
Authorization: Bearer <your_token>

# Try user_id = 1 (you), then 2, 3, 4 …

          Root cause: In account.py → get_user_profile(user_id), the server only calls

          the requested user_id. The fix: add if g.current_user.id != user_id and g.current_user.role != 'admin': abort(403)
